# ADR-008 — Provider-neutral observability core with provider-specific monitor UI

- Status: accepted
- Date: 2026-11-04

## Context
Users need visibility into task execution, agent activity, blockers, approvals, and progress without coupling the Blueprint to one coding-agent interface.

## Decision
Observability semantics and data contracts belong to the provider-neutral Blueprint core. The monitor UI is implemented by provider adapters. The first implementation is `developer-ai-init-monitor`, an OpenCode TUI plugin that renders core observability data in OpenCode's sidebar.

## Ownership and runtime
This Blueprint repository owns and versions the monitor specification and OpenCode plugin source. The initializer installs and configures it in projects generated by the Blueprint. At runtime, the plugin runs inside OpenCode and reads the generated project's canonical `.blueprint/` state. It does not modify OpenCode itself or require a separate service.

## Constraints
- The core remains usable without a monitor.
- The monitor is a presentation and observability layer, never a second source of truth.
- Task state, approvals, agent assignments, and handoffs remain canonical in `.blueprint/`.
- OpenCode-specific event handling, TUI components, and sidebar rendering stay inside the OpenCode adapter.
- Other provider adapters may implement different UIs against the same core contract.

## Consequences
- Define a provider-neutral observability contract before implementing the OpenCode plugin.
- Specify data ownership, update events, freshness, and degraded/manual modes.
- Validate compatibility with OpenCode 2.2.5 before claiming support.
- Sequence the monitor with TASK-009 or a clearly scoped adapter subtask.
