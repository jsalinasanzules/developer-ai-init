# Development Conventions

- Repository documentation is clear, professional English; discuss decisions with the user in Spanish unless requested otherwise.
- Requirements are normative and testable; use MUST/SHOULD/MAY consistently.
- Use stable IDs for specs, tasks, and decisions.
- Use ISO 8601 dates.
- Markdown is human-readable documentation; JSON is machine-readable registry/configuration.
- Keep provider-specific assumptions inside adapter documentation.
- Cite current official provider documentation for provider-native configuration.
- Never commit secrets or tokens.
- Update memory and task records with meaningful changes.
- Never mark work done without observed verification evidence.
